# Seedance 2.5 导演

## 使用边界

先确认当前供应商真实支持的模型、模式、时长、画幅、清晰度和素材上限。这个 Skill
只负责导演规划和提示词，不调用视频接口、不消耗积分、不把外部仓库脚本当作项目执行链。
项目已验证的协议、尺寸、参考资产和失败终态优先于本文件的概念性能力描述。
本 Skill 是 prompt-authoring-only 质量层：只向 Agent 返回字段级补充、冲突、缺失和单变量修复建议，由 Agent 写入项目固定公开合同；不得产生第二套提示词、覆盖用户事实或把本文件原文附加到供应商请求。

## 主模式

为每次请求只选择一个主模式：

- `basic-multimodal`：普通 4-30 秒视频。
- `timestamp-30s`：恰好 30 秒且需要精确时间轴。
- `long-video`：30-180 秒长叙事。
- `video-extension`：从源视频首帧或尾帧续写新增区间。
- `video-edit`：对指定对象或时间区间进行局部修改。
- `clay-renderer`：使用粗白模或细白模控制动作、构图、材质和灯光。
- `seamless-transition`：保护两段源视频，只生成中间连接段。
- `multi-grid-storyboard`：按多宫格分镜顺序生成连续镜头。

人物表演、多人锁定、音色、BGM 移除、视角重建和绿幕是附加能力，不替代主模式。

项目运行时路由：15/20 秒默认读取普通视频规则；30 秒默认读取精确时间轴规则；用户明确提出续写、编辑、白模、无缝转场或多宫格分镜时，改读对应专用 reference。静态图片帧不使用本 Skill，继续按项目的 Seedance 2.0 静态帧规则生成。

按需附加 reference：真人表演、对白、情感冲突、体育或访谈读取 [realistic-direction-patterns.md](references/realistic-direction-patterns.md)；多人、对话、餐桌、车内或会议读取 [multi-character-blocking.md](references/multi-character-blocking.md)；用户要求参考结构、复刻镜头或模仿节奏时读取 [example-adaptation.md](references/example-adaptation.md)；出现失败、漂移、变形、模糊或重试时读取 [failure-diagnosis.md](references/failure-diagnosis.md)。这些 reference 只补充当前任务，不改变用户明确的素材、时长、比例或供应商能力。

模式 reference：普通/15/20 秒、30 秒时间轴、长视频、续写、编辑、白模、无缝转场和多宫格分镜读取 [mode-routing.md](references/mode-routing.md)。

## 提示词合同

按需使用以下字段，每个非空字段单独成行：

1. 素材绑定：当输入提供有序的 `referenceMaterials` 时，先输出“素材绑定”字段；数组第 N 项必须对应唯一别名 `@图片N`、`@视频N` 或 `@音频N`，按输入顺序逐项写出其唯一主职责、作用范围和不继承内容，不得新增、删除、重排或猜测素材。这里的编号和职责由本 Skill 根据当前输入生成，应用代码不得代写 Agent 的公开提示词正文。
2. 动态意图：一句话说明主体、主要事件和视觉目标。
3. 全局设定：只写贯穿本片的场景、材质、风格、声音和摄影原则。
4. 起始可见状态：写首帧已经可见的主体、道具、空间、站位、朝向和接触关系。
5. 时间段动作：多事件按阶段或连续时间段写“起点 → 动作与触发 → 可见衔接 → 终点”；“动作与触发”同时承载准备、接触/受力、结果、恢复和主体反应，不另设顶层触发或主体动作字段。
6. 单一主运镜：每镜只保留一个有动机的景别、机位或运镜。
7. 环境压力与视觉母题：写具体环境压力及可听见或可看见的锚点。
8. 视觉风格与光色：写色板、主光方向、材质反应和具体质感。
9. 声音意图：明确对白、语言、说话人、环境声、动作音、音乐、静音和字幕策略。
10. 结束画面：写最终可见的构图、姿态、道具位置、光色和声音状态。
11. 连续性锁：只保留身份、数量、服装、道具归属、空间方向、轴线、光向和声音等高代价约束。
12. 针对性约束：只列本镜头最可能且重做代价高的错误。

公开执行提示词不得输出 `A线`、`B线`、`主线`、`副线`、`钩子` 等叙事规划标签；如果这些词表达了创作意图，必须转换为当前镜头可见的主体、事件、动作或声音，否则省略。

当输入提供 `framePlan.frames` 时，Agent 必须在同一轮输出中返回完整公开 `videoPrompt` 和逐帧动作计划：沿用每帧既有的 `id`、`sequenceIndex`、`startSecond` 和 `endSecond`，为每个真实动作节点填写具体的 `startPrompt`、`actionPrompt`、`transitionPrompt`、`endPrompt` 与 `imagePrompt`，并在 `videoPrompt` 的“时间段动作”中逐段直接写出相同的时间范围、起点、动作与触发、可见衔接和终点。`framePlan.frames` 只是 `videoPrompt` 的结构化镜像，不能替代公开提示词中的时间段正文。所有描述必须根据相邻帧的真实可见状态填写，不能使用重复的通用阶段句；应用代码只能校验、保存和转发，禁止拼接、补写、删改或从 `framePlan` 生成 `videoPrompt`。

## 连续性和物理因果

- 首尾帧只控制一个镜头的起始和结束，不代表所有镜头都继承上一镜尾帧。
- 硬切、插入、遮挡、甩镜和 Match Cut 独立设计；连续动作才使用已验收的真实尾帧交接。
- 多人必须写清左右/前后、朝向、视线、接触关系、道具归属和声音身份。
- 人物动作必须有可见支撑、接触、受力、距离和结果；情绪必须落到眉眼、嘴角、下颌、呼吸、视线、手部或身体变化。
- 未声明的人物、道具、对白、品牌和剧情事件不得凭空加入；参考素材中的背景、文字、水印和声音不得默认继承。

参考素材只在提示词中承担语义职责：模型应依据当前 `referenceMaterials` 生成素材绑定和公开提示词；媒体 URL、内部 ID 和供应商请求体不属于提示词。服务端可以在提交前校验绑定完整性并把已验证的素材映射到供应商请求，但不得替模型补写、改写或伪造 `@` 引用正文。

## 时间和编辑

- 单一动作使用自然段落；多事件默认使用“阶段 + 可见结束状态”。
- 只有音乐、口型、固定节拍或用户明确要求时，才使用逐秒时间轴。
- 时间段必须连续、不重叠，下一段起点必须继承上一段终点，不能机械逐秒切碎。
- 续写只描述新增区间，并明确前向/后向边界、添加时长、保留原片和自然接入方式。
- 编辑必须写位置或时间、目标对象、操作和 preserve 项；转场必须保护两个源视频不变。

## 质量审计

回复前检查主模式、素材标签、素材职责、时间轴、对白容量、动作因果、镜头运动、空间关系、声音策略和连续性是否互相冲突。生成失败时先分类为身份、素材绑定、构图、动作、物理、音频或时间问题，只修改一个已定位变量，并保留已验收状态。内部模式、模型理由、平台规则、执行提示词、来源文件和 API 信息不得进入公开结果。
