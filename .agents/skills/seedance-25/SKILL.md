# Seedance 2.5 供应商适配器

## 使用边界

本 Skill 只负责已验证的 Seedance 2.5 能力、模式、时长、画幅、清晰度和参考素材限制的适配，不调用供应商接口、不消耗积分，也不创建第二套短剧导演规则。用户事实、项目资产、已验收尾帧和服务端供应商协议优先于本文件。

短剧制作包和 /api/drama/analyze 的公开视频 Prompt 必须服从 canonical drama-video-director Skill 的 Seedance 2.5 五层契约（seedance25-prompt-adapter@1.1.0）：【参数】、【参考】（无实际素材时省略）、【公共总规范】、【时间轴】、【收尾】。公共不变事实只写一次，一个公开时间轴段可以覆盖多个连续内部帧，按叙事节拍合并微镜头。完整正文目标 1200–1800 个 Unicode 字符，2500 是包含标题、标点与空白的提示阈值；超限只提示作者压缩，不阻断交稿或视频提交，不自动截断。小墨 6.3 只提供内部导演判断，禁止回退为逐镜重复场景、光影、色调、人声和音效的旧公开卡片；内部起点、动作、衔接、终点继续只保存在 framePlan、表演、连续性和质量门禁字段中。

### Seedance 2.5 压缩与公开段落规则

字段与表达依据用户当前《Seedance2.5_通用提示词生成适配器_v1.0.md》（frontmatter version 1.1.0），项目副本为 `.agents/skills/seedance-25/references/prompt-adapter.md`。公共身份、场景、光色、声音政策各写一次；时间轴使用连贯自然语言，只写本段新增动作、触发、结果、主运镜、原句和必要的局部声音。不得再输出逐镜重复的场景/画面内容/光影/色调/台词/人声/音效多字段卡；无变化不写“局部变化”。

同主体、同空间、同因果链、同连续运镜的内部微镜头可以合并成一个公开时间段，普通 21–30 秒建议 4–6 段，仅是压缩建议；有新角色出入、关键结果、场景/时间/轴线变化、对话关系转折或真实硬切时保留可辨识边界。内部 framePlan 继续保留对白自然窗口、静态状态与硬切证据，公开段边界对齐内部帧边界，不要求两者数量相同；dense-30s 的真实 7–10 次硬切不能被压缩隐藏。完整正文目标 1200–1800 个 Unicode 字符，2500 仅提示，覆盖来源文档的旧 2000 字硬限；不阻断、不自动截断、不改变逻辑片段数。保留全部已锁定原句与声音身份，不按文档示例删除台词或新增画面字卡。

## 模式路由

每次请求只选择一个实际需要的供应商模式：

- basic-multimodal：普通短视频。
- timestamp-30s：用户或项目明确要求精确30秒时间轴。
- long-video：用户明确要求长叙事。
- video-extension：从已验收源视频继续新增区间。
- video-edit：修改指定对象或时间区间。
- clay-renderer、seamless-transition、multi-grid-storyboard：仅在用户明确提出且供应商能力已验证时使用。

模式选择不决定逻辑片段数量、镜头数量或硬切次数。每个逻辑片段的时长和内部镜头密度来自当前项目配置与剧情事实；30秒、8帧或7—10次硬切不是所有请求的默认规则。

## 供应商适配规则

- 先按画幅设计构图：9:16优先单人、双人过肩、前中后景或上下纵深；16:9允许横向关系、长桌群像和空间展开。不得把横屏站位直接裁切成竖屏。
- 参考素材按稳定 alias、role、purpose 和顺序传递；不新增、删除、重排或猜测参考图，不把参考图编号写成供应商执行数据。
- 首帧和尾帧只按用户显式选择或项目已验收连续性状态提交；下一镜只使用上一镜已验收实际尾帧，不复制同组首镜起始状态。
- 多人必须保留左右/前后、视线、支撑面、接触关系和空间锚点；画面过载时拆分信息，不缩小主体或使用虚化掩盖遮挡。
- 硬切只切换视频片段，不重置世界空间：跨片段携带的角色、道具、环境和轴线必须从上一镜出口状态继承；只有明确写出移动路径、触发和到达结果时才能改变站位，下一镜首个帧段必须重复空间锚点。
- 五层公开正文及每个时间轴段的时间范围、主体动作、触发与结果、景别/焦段/机位、主运镜、台词和局部声音由 Agent 直接生成；应用服务端只校验、拒绝和保存，不拼接或改写。
- 直接对白使用“说话人说：‘实际台词’”；按自然语速分配对白游标，不能用异常加速塞入短时间段。

## 内部质量协作

本适配器与 canonical 导演 Skill 共用一份 authoring draft。内部 framePlan.frames[] 必须连续覆盖当前逻辑片段，保留真实时间边界、动作差异、对白时间、连续性、静态画面状态和硬切事件。每帧必须具备“主体动作→触发原因→可见结果→声音锚点”因果链，不能用静态站桩填充剩余时长。每次切换必须带来新的角色反应、关系、动作、道具、空间或结果信息；只有用户或项目明确的密集剪辑策略才执行相应硬门禁。

服务端质量门禁负责检查画幅构图、主体清晰度、遮挡、对白容量、相邻镜头重复、硬切信息差异、角色服装连续性和参考 alias 一致性。Agent 必须在首次返回前完成同一份门禁自检并直接输出可用成品；失败时返回聚合后的具体阻断项，不展示或提交半成品。正常制作包路径最多允许一次同渠道完整修订，修订仍失败时结束本次 authoring；不得自动换渠道或重复重建，只有用户显式重试才开启新的 authoring run。
每次返修只改变一个已定位变量；如果是连续性、对白边界或动作因果失败，必须修正对应事实链，不得用换机位、换模型或改写无关风格字段掩盖问题。
