# 短剧视频导演层

这是一个 prompt-authoring-only 的导演方法层。它只把导演判断写入现有制作包字段、静态帧字段和视频公开合同，不创建第二套提示词，不提交供应商任务，也不覆盖项目资产、供应商协议和已验收尾帧事实。

## 默认导演质量层

只要任务涉及短剧制作包、分镜、视频提示词优化、片段首尾帧、镜头切换或运镜，自动启用本层；用户只需要提供剧情/对白、人物与场景、画幅/时长、参考素材、风格和明确禁用项，不需要重复手写导演规则。普通问答和与视觉生产无关的文本不启用本层。

- 用户明确事实、尺寸、时长、风格和修改要求优先；项目资产事实和已验收连续性状态优先于推断。本层可以补齐导演表达，但不得凭空增加人物、道具、地点、关系、对白或剧情结果。
- 不要只做同义改写。先提炼本段唯一戏剧职责、主体动作、对手/环境的可见反应和镜头结束状态，再把它们落到景别、机位、构图、焦段、主运镜、视线/轴线、声音和连续性。
- 只要用户描述包含对白、多个动作节点、人物反应或信息转折，默认按多镜头导演方案组织；镜头数量、内部时间段数量和切换次数都由真实可见节拍决定，不固定为 10 个时间段、9 次切换或统一的 3/4 段结构。需要切换时声明内部切镜次数，并为每个切点写完整摄影事件；只有用户明确要求单镜头，或内容确实只有一个连续动作时，才保持连续镜头。
- 连续镜头全段只保留一条连续主运镜；内部切镜时，每个切后段各自只保留一个主摄影选择，避免在同一段混用推、拉、摇、移和环绕。每个时间段都写“起点 → 动作与触发 → 可见衔接 → 终点”，但这只是信息契约，不是固定句式；动作必须有支撑/接触/受力和可见结果，表演必须落到视线、呼吸、嘴角、下颌、重心、手部、道具或环境反应。
- 制作包中的 `videoPrompt`、`framePlan`、`performancePlan`、`continuity`、`lens`、`cameraMotion`、`entryState` 和 `exitState` 必须一次写成可生产数据；`framePlan` 是公开视频正文的结构化镜像，不由应用层事后拼接。输出前执行动作差异、镜头事件、对白时长、轴线、资产引用、NPC、光源和画面清晰度检查。
- 用户输入过于简略时，采用最小合理导演补全并保持可修改；只有缺少会改变剧情或资产绑定的事实时才提问，不把“请补充运镜”转嫁给用户。

## 制作包最小输入协议

制作包的目标是让用户只提交“配置 + 剧情来源”，而不是手工填写导演表。用户可见的最小输入为：

- 输出配置：`画幅`（如 9:16 或 16:9）、`分辨率`、`总时长`；帧率、声音模式和模型仅在界面已有配置或用户明确指定时读取。
- 剧情来源：当前集 TXT、小说片段、情节 TXT 或用户明确提供的剧本正文。
- 当前项目已有的正式角色、场景、道具、线索、制作包模板和已锁定生产方案由系统自动传入，不要求用户在请求中重复粘贴。

Agent 必须从剧情来源和正式资产中自动完成：剧情事实提取、对白归属、角色/场景/道具绑定、戏剧节拍、动作因果、表演反应、画幅构图、镜头数量、切镜事件、景别、机位、焦段、主运镜、声音和连续性字段。用户没有提供镜头数量、运镜清单、固定帧数、NPC 分布或逐段时间线时，不得向用户索要这些导演细节，也不得用空字段或固定模板代替推导。

只有缺少会改变身份、剧情结果、正式资产绑定、空间拓扑或用户明确禁用项的事实时才提问；提问必须指出唯一缺口。缺少摄影细节、动作拆分、反应、镜头边界或画幅构图时，由本 Skill 做最小合理补全，并在不改变剧情事实的前提下生成可修改制作包。

## 画幅适配编译

画幅不是只写在输出参数里的尺寸标签，而是镜头编排的前置条件。先选择画幅构图方案，再编排镜头；禁止把同一套横向站位、景别和运镜文字直接裁切或替换比例后复用。世界空间坐标、人物身份、入口方向、光源方向和 180 度轴线保持不变，屏幕构图、人物可见数量、景别和相机路径随画幅重排。

- `9:16` 采用纵向层级方案：优先单人中近景、过肩、前景/中景/后景叠层和有限宽度的双人关系；群像只在确有空间交代职责时使用，不为了“全员入画”缩小主角或强行使用超广角。默认一张可读画面只承载一项主要人物关系，近景保留完整头顶、下巴、主要衣领和关键手部；九人“始终在场”表示世界连续性，不表示每个镜头都要清楚展示九人。
- `16:9` 采用横向关系方案：允许长桌、通道、三人权力关系和群像定场在同一画面中展开；横移、摇镜和横向跟拍只有在空间关系或视线转移需要时使用，近景仍按主角信息优先，不承诺所有背景人物都具备人脸近景清晰度。
- 其他画幅先按可见宽度、主体数量和场景拓扑生成等效构图方案；不得把 9:16 或 16:9 的默认策略硬套到方形或自定义比例。
- 画幅适配是强可执行的构图决策，但不是固定镜头名额或运镜配额。每个镜头仍根据当前画面能否清楚承载事件决定景别、人物数量和主运镜；若用户同时要求“竖幅、多人全部清晰、完整大厅和完整全身”，应优先保证剧情主体与脸部可辨，并将无法同时满足的范围降为远景/背景或提示为构图风险。

### 清晰度合同

清晰度是默认生产要求，不是用户额外填写的风格偏好。除非用户明确要求背影、虚焦、浅景深或氛围性模糊，否则所有出镜主角、关键 NPC、剧情道具和场景锚点都必须在当前景别下清楚可辨。

- 禁止无意的人脸模糊、焦点漂移、过度浅景深、雾气、泛光、粗颗粒遮脸和过强运动模糊；需要表现空间时使用真实前景遮挡、尺度递退、受光差异和可读陈设，不用虚化掩盖结构。
- 9:16 信息过载时拆成建立、关系、反应和细节镜头，不把多人缩成一排；16:9 信息过载时保留横向关系，但把主次清晰度写进构图，不能让所有人都变成无辨识度的小人。
- 近景默认保留完整头顶、下巴、主要衣领和关键手部；全景默认保证主要人物、空间结构和动作方向可辨。颗粒、逆光和低饱和不能遮挡五官、手部、道具接触面或场景轴线。
- 模糊必须写出叙事原因和对象，例如“萧炎背影短暂虚焦，纳兰脸部保持清晰”；没有明确对象和原因的“背景虚化、电影感浅景深”视为质量风险。

## 反模板化编排原则

固定的是字段语义、时间连续性和可验收事实，不是提示词句式、镜头数量或画面套路。导演判断必须先服务当前剧情，再落到字段；不能因为模板里有某个字段，就为它凭空制造动作、道具、NPC、反应或运镜。

- 先在内部提取“戏剧节拍 → 可见状态 → 摄影变化”的事件图，再写公开提示词；公开结果只保留能影响画面、声音、连续性或生成稳定性的事实，不输出内部检查清单。
- 相邻时间段必须有真实的新信息，但不要求每段都换景别或每次都切镜；能在同一连续镜头里完成的视线、呼吸和小幅受力应合并，只有同一画面无法清楚承载的新信息才增加帧或切镜。
- 不复制上一镜或同一镜的“全局设定、视觉风格、NPC反应、镜头目的、起点句式和结尾句式”。全局字段只锁定跨段不变量，时间段只写本段新增的可见变化；同一设定若没有新的作用就不重复展开。
- 同一项目可以有不同的镜头节奏：有的镜头以人物表演为主，有的镜头以道具结果、空间关系、对手反应或静默停顿为主。不要为了凑齐人物、道具、NPC、特写、推镜和反打而机械排布镜头。
- “起点、动作与触发、可见衔接、终点”是最低信息结构，不要求每一段使用相同长度、相同语法或相同修辞。事实不足时省略无依据的细节；不要用“自然反应、保持状态、情绪加剧、电影感推进、当前冲突信息”等占位语填空。
- 生成前做一次抗模板检查：若相邻段只更换形容词、若多个镜头共享同一摄影目的、若每个镜头都使用相同景别和运镜、若全局设定被逐段复制，则合并、改写或重新拆分；质量优先于字段数量。

## 分镜方法借鉴：把导演判断落到可见画面

参考专业文字分镜的有效方法，但不照搬固定配比、镜头名额或题材套路。优先级为物理可行性、叙事节奏与情绪、镜头多样性；三者冲突时，前两者优先。镜头服务信息，不为炫技增加机位。

- 镜头经济性：每个镜头至少带来一种新信息——关系、动作结果、反应、空间、道具压力或留白。能在同一画面完成就合并，信息重复、情绪重复和功能重复的镜头删除或合并。
- 看图说话：画面正文只写屏幕上能看到的进行中瞬间。人物情绪要落到动作、重心、手部/道具接触、眉眼、嘴角、呼吸或视线；不要用“她很悲伤”“气氛紧张”替代可见事实。
- 光源与纵深：每处亮度都要有来源、方向、落点和衰减；纵深优先来自真实前景遮挡、尺度递退或受光差异，不用雾、泛光、虚化和颗粒掩盖空间。体积光、雾和高光溢出只有在场景事实支持时才加入。
- 景别、焦段和机位是叙事工具：定场优先交代关系，侧45度适合保留对话张力，侧面只用于疏离/回避等明确情绪，俯仰角必须有权力或空间理由，焦段必须与空间尺度和人物距离相容。不要为追求“高级”强行使用广角畸变、长焦压缩或极端角度。
- 连续性：对话默认守住180度轴线和左右视线；相邻同主体镜头尽量有足够的角度、景别或焦段变化，避免跳切；大景别到大特写需要动作、视线、图形或声音承接。上一镜的运动可以接下一镜的运动，也可以有情绪理由地落到稳定镜头。
- 台词与画面：长台词需要动作、听者反应、道具局部、双人关系或环境留白来分担信息；禁止人物长时间站桩说话，也禁止为了打破站桩而添加无意义小动作。切镜必须改变观众的情绪、信息或注意力。
- 表演的三通道可以组合使用：大动作层承载关系和空间，小动作层承载暗流，微表情/呼吸层承载细微转折。强情绪允许用突然的静止、停顿或拉远表现，不把每个高潮都写成推近、嘶吼和夸张特写。
- 激进手法只在有叙事理由时使用：手持烈度、荷兰角、极端俯仰、环绕、滑动变焦和复合运镜都不是默认配额；没有足够情绪或空间依据就不用。平静段可以使用极慢微运镜保持流动，但不强行追求“全片运镜多样”。

## 共同前置审计

任何镜头先回答以下问题，再写公开提示词：

1. 此刻主体想要什么，阻力来自哪里，镜头结束时发生了什么可见变化。
2. 谁在什么位置、以什么姿势、借助什么支撑、对谁或什么做什么。
3. 主体的视线、屏幕方向和 180 度轴线如何保持；多人必须有同一参照系。
4. 当前镜头的唯一戏剧职责是什么：情绪变化、动作推进、信息揭示或压力增加。
5. 哪个具体环境压力、身体微动作和声音/视觉锚点让镜头不只是空泛氛围。

原文事实、资产事实、合理推断和导演建议必须分开。没有原文或资产依据时，不得增加人物、道具、关系、地点或剧情事件。

## 资产事实与提示词统一编译

制作包不是把多个 Skill 的完整提示词串联起来，而是由本 Skill 统一编排资产、剧本、静态帧、表演、摄影和视频模块。角色、场景、道具的资产事实先形成唯一事实底稿，后续所有公开字段都从同一底稿取值；这样可以避免角色在资产卡、`imagePrompt` 和 `videoPrompt` 中被重复改写。

- 处理小说、剧本或人物资产提取时，内部按“原文明确事实 > 项目已登记资产事实 > 由身份/时代/地域/阶层/技术水平作出的最小推导 > 设计建议”分层。推导和建议不得伪装成原文事实；没有依据的细节省略或标记待确认，不悄悄锁进制作包。制作包只保留已确认事实、必要的可解释推导和用户明确要求，不输出原文引用、分析报告模板、推导标签或内部思维过程。
- 角色事实固定整理为六项：年龄、性别表达、肤色/身体标记、发型发色、最有辨识度的五官、服装轮廓与材质。沿用现有字段，不新增平行字段：`description` 只写身份与用途；`visualIdentity` 写年龄感/性别、肤色、五官、发际线和发型；`styling` 写服装层次、固定配饰、鞋靴、材质与穿着逻辑；`colorPalette` 写角色固有色；`consistencyRules` 锁定脸部、比例、发束、服装层次、固定配饰、固有色和显著标记。
- 人与物按“是否需要独立制作一个资产”分离：身体标记、发型和贴身饰品留在角色；武器、防具、工具、容器、信物、关键剧情物和可复用场景物件独立归入道具。道具事实优先锁定轮廓/尺寸关系、材质、固有色与磨损、关键识别细节、归属/佩戴位置和已知状态变化；持握、挥动、使用过程属于镜头动作，不写进静态道具基准图。
- 场景事实优先锁定空间拓扑、入口出口、门窗、固定陈设、地面材质、光源方向、通道和人物可用支撑面；可脱离场景独立复用的物件仍归道具。服装、道具和场景的材质、剪裁、配色及工艺必须符合当前项目已有的时代、地域、环境、阶层和技术水平，不能用无依据的“高级、电影感、精致设计”替代可画出的事实。
- 资产基准图与镜头提示词承担不同职责，不能互相覆盖：资产基准图的公开提示词固定使用六段 `主体与资产类型 → 身份/结构锚点 → 可见状态与材质 → 构图与画幅 → 光色与风格 → 负面约束`；镜头 `imagePrompt` 继续使用静态帧的五类可选短段 `画面主体、可见状态、构图与空间、光色与风格、针对性约束`，只冻结当前瞬间；镜头 `videoPrompt` 使用视频适配器的完整字段和真实时间段。镜头可以引用资产事实，但不得复制完整资产档案、道具制作清单或内部规则。
- 三类提示词都遵循同一编译顺序：先绑定当前真实角色、场景、道具和线索，再写身份/结构锚点与可见状态，最后写构图、光色、动作、声音、连续性和针对性约束。`characterCodes`、`locationCode`、`propCodes`、`clueCodes`、参考图职责和公开正文必须相互一致；一个镜头未绑定的道具、服装、角色或地点不得因为其他模块的文字而进入画面。
- 本制作包唯一导演 Skill 内部包含资产事实、场景/NPC、摄影、表演、关键帧、静态帧、视频和制作包字段模块；生成制作包时不再把资产图片 Skill 作为第二套完整提示词规则拼接进来。Seedance 2.5 只作为供应商适配层补充当前时长/模式和参考职责，不得覆盖本 Skill 的事实、字段或连续性规则。

## 场景 NPC 策略

- 场景资产的 `backgroundNpcPolicy` 是背景群像规则，`auto` 由场景类型、空间容量、景别和剧情功能判断，`required` 必须在关键帧和视频中安排合理数量、密度、位置与行为结果，`forbidden` 则禁止背景 NPC。
- NPC 只作为不具名背景群像，不进入主角色 `characterCodes`、角色锚点或独立角色资产；只有具有明确剧情身份的 NPC 才升级为正式角色资产。
- 场景全景基准图始终保持高清、无人、无文字的单视角建立图；NPC 只写入实际镜头的关键帧、视频时间段和可选构图参考。没有配置策略时按 `auto` 判断，不能把“没有配置”误读成“禁止人物”。
- `auto` 场景需要 NPC 时，必须明确写数量范围、前中后景分布、群体姿态/行为和不抢主角注意力的景深关系；不需要时明确使用空位、空通道或画外人声等事实依据。不得为所有场景套用固定人数。
- `required` 场景应在 `backgroundNpcPolicy.countRange` 声明本场允许人数范围；没有稳定槽位表时，每个受事件影响的时间段可以使用旧版可校验语法：`NPC群像：N名；分布：前景X名、中景Y名、后景Z名；密度：具体密度；反应：具体可见反应`，且必须满足 `X+Y+Z=N`、`N` 落在 `countRange` 内。已经建立稳定槽位表时，优先使用：`NPC连续性：可见槽位：slotId...；世界锚点：固定座位/墙边/门侧等；状态变化：当前槽位相对上一段的视线、肩线、手部、呼吸或收声结果`。不能用全局人数代替逐段结果，也不能让同一段的起点、动作、衔接和终点互相矛盾。

### 稳定群像槽位与反克隆

“前景两人、中景一人”只描述画面层级，不能作为跨镜头身份。需要连续出现的群像必须先建立世界空间槽位，再把槽位投影到每个镜头；屏幕左/右、前/中/后景只是当前构图结果，不能成为身份依据。

- 每个需要连续性的 NPC 槽位绑定稳定的座位、墙边、门侧、通道或其他世界空间锚点，并保留匿名 `slotId`、默认姿态、视线目标和基础行为；不在本镜可见的槽位继续存在，不能被下一镜重新分配给另一名路人。
- 同一群像共享时代、服装类别和风格，但每个重复槽位至少有一项稳定差异：发束、袖色、脸型、身形、配饰、坐姿或衣料层次。没有正式角色资产时使用“群像资产 + 槽位变体”，禁止把七名 NPC 生成为同一张脸的复制品。
- 每个镜头只声明当前可见槽位及其状态变化：看向谁、何时延迟抬眼、肩线是否收紧、手是否停住、是否贴墙或继续低头。隐藏槽位不写成新人物，不改变原座次，不遮挡主角脸、手和关键道具。
- 画面需要机器验收时，稳定槽位段必须至少包含“可见槽位、世界锚点、状态变化”三项；画面构图可以另外写当前的前/中/后景投影，但屏幕层级不能取代世界槽位身份。
- 需要近景、持续对白、反复出现或承担剧情信息的 NPC 自动升级为正式角色资产；普通无名旁听者只维持可读的轮廓、服装变体和动作结果，不抢占视觉中心。
- Agent 输出的群像反应必须引用稳定槽位或世界锚点，不能只写“前景两人”“中景一人”“其余人保持不变”。质量门禁只把数量/分布作为事实校验，把槽位连续性、变体和反应变化作为连续性校验。

## 摄影与画面

- 景别、焦段、机位、构图和主运镜必须共同服务一个可见的信息或动作变化。
- `单一主运镜` 必须写成可执行路径：至少包含机位/景别或角度、固定/运动方式、运动方向或起止关系，以及它服务的唯一可见变化；“中轴推进”“电影感”单独出现不算完整摄影指令。
- 每镜只保留一个主运镜；按不同运动类型判断冲突，不按同一运镜在构图、摄影字段和公开 Prompt 中的重复出现次数判断。不要把推、拉、摇、移、旋转等互不相容的运动堆在一起。
- 动作镜头先把运动拆成三类：主体运动、相机运动、环境运动。默认各自只保留一个主导运动，复杂场面可以例外，但必须说明优先级和谁服务谁；这是动作可读性的整理规则，不是按题材或时长阻断生成的固定配额。
- 主体运动必须交代支撑、接触或受力、方向/距离和可见结果；相机运动必须能跟上主体或主动引导结果，不能与主体速度、方向和屏幕空间互相打架。主体快跑、转身、坠落、挥击等动作若会出画、失去受力或无法承接，优先修正机位路径、预留运动空间或降低动作复杂度。
- 环境运动只承担一个主要的可见压力或节奏作用；雨、风、烟、碎片、人群等其余元素降为静态氛围或弱化表现，避免遮挡脸、手、道具接触面和动作结果。动作、相机和环境的方向/速度不一致时先标为质量风险，再做最小改动修正。
- 光影必须能回答光从哪里来、照到谁、如何衰减、被什么遮挡，以及材质如何反应。
- 纵深至少由前景框景或遮挡、中景主体、背景环境中的真实元素构成；不要用“有层次”代替具体空间。
- 景深、焦外、雾气和颗粒只用于承载叙事重点，不得遮盖需要识别的脸、手、道具或连续性状态。
- 背景不是装饰：需要识别的门窗、墙面、桌面、通道和陈设必须保持清晰可辨；禁止用大光圈人像虚化或过重雾化掩盖场景结构。
- “电影感、氛围感、高级感、震撼”不能单独作为视觉设计，必须翻译成光色、材质、构图、运动或可见状态。

## 表演与节奏

- 把抽象情绪翻译为眉眼、视线、呼吸、嘴角、重心、手部、身体和道具的可观察变化。
- `performancePlan.emotionalObjective`、`emotionalArc` 和 start/middle/end 必须在制作包生成阶段一次写全；情绪目标不能只写“自然、到位、逐步变化、结果成立”，每个阶段至少绑定一个当前镜头的具体视线、呼吸、受力、手部、身体、道具或环境结果。导入后不得再依赖笼统兜底才变成可生产数据。
- 动作按“起点状态 → 触发/受力 → 动作过程 → 可见结果或反应”组织；每个时间段的终点必须能成为下一段的起点；相邻段不得复制同一动作块，至少要有一个可验收的动作、视线、呼吸、姿态、手部、道具或环境差异。
- 动作分镜的核心不是罗列动作名，而是让观众看见因果链：准备或蓄力、接触/受力、方向与轨迹、受影响对象、结果和恢复/反应。没有接触面、支撑、阻力或结果的“挥动、冲向、撞击、倒下、爆炸”等词只能作为待补事实的警告，不能直接当作可执行动作。
- 一个时间段只安排一个主动作变化；同段内的次级反应必须由主动作触发，并落到人物重心/呼吸/视线/手部、道具位移/变形或环境受力中的至少一项。不要把多个独立高潮压进同一段，再用“快速完成”掩盖缺失的动作节点。
- 多帧镜头不得让所有片段沿用同一张构图；在不破坏轴线和连续性的前提下，根据真实信息安排景别、机位/构图、站位、视线、手部、重心或道具结果的可见变化，不能只在文字中换同义词。
- 对白先核算自然语速和停顿，再决定镜头边界；重大冲击前保留必要停顿，高潮后给出结果或反应；起始、中段、结束三个表演阶段必须形成不同的可见情绪递进，不能只替换情绪形容词。
- 一个镜头只保留一个主戏剧变化，但允许由它触发多个可辨认的次级反应；required NPC 群像必须随主事件至少变化一次数量、分布、姿态、视线或收声；非人物镜头、道具特写和环境切镜必须有信息、压力或转场职责，不按固定比例机械添加。

## 自适应关键帧与镜头事件

- 按真实动作、反应、道具结果、空间揭示和摄影切换事件识别当前镜头的可见事件；Agent 模式没有默认帧数。先列当前镜头的可见事件节点，再决定 2–9 帧：动作、表情/视线、道具状态、对手或 NPC 反应、空间揭示、景别/机位/构图切换。
- 以冻结的可见状态为计数单位：入口和出口是必要边界；只有当新增状态无法与相邻状态在同一张画面中表达时，才增加关键帧；同一时刻同时发生的结果可以合并在一帧。视线转移、信息揭示、人物反应、空间关系变化或明确切镜必须有对应新关键帧。
- 2–9 只是允许范围，不是分配模板；不能按镜头时长、提示词长度、角色数量、NPC 数量或参考图数量套用统一帧数。不同镜头只有在可见事件集合相近时才可以使用相同帧数；事件复杂度不同却全部使用同一数量时，必须标记为质量风险。固定帧数只在用户主动选择固定方案时执行。
- 每帧必须写相对上一帧的可见变化。相同机位可以连续使用，但人物表情、姿态、重心、视线、手部、道具受力或环境结果至少有一项发生可辨识变化；画面状态和摄影状态同时重复时不得生成重复帧。
- 在 `framePlan` 中，除第一帧外，每帧 `startPrompt` 必须原样承接上一帧 `endPrompt`；新的变化只写入本帧动作、衔接和终点，不能在新段起点凭空改写姿态、视线、道具或 NPC 状态。
- 动作复杂度按可见事件拆分而不是按秒数拆分：入口状态 → 准备/触发 → 接触或受力 → 动作结果 → 反应/恢复。只有相邻节点不能在同一画面中清楚表达时才增加帧；同时发生且能共同验收的受力、结果和反应可以合并。
- `framePlan.frames` 中，`startPrompt` 只承接已成立的入口状态，`actionPrompt` 写发生中的动作、方向、接触和受力，`transitionPrompt` 写动作如何把画面/状态交给下一节点，`endPrompt` 写冻结后的结果或反应。四者不能都写成同一个动作概述，也不能把尚未发生的结果提前写进起点。
- 每镜必须先明确镜头模式：`连续镜头` 或 `内部切镜`。3 张或更多关键帧只表示有多个可验收状态，不自动表示发生了切镜；若未声明内部切镜，所有帧都在同一连续镜头内完成。
- `连续镜头`只能有一个连续的主运镜；帧边界是动作/表演/道具状态锚点，不是剪辑点。不得把“帧数”“时间段”或“视线变化”写成隐含切镜。
- `内部切镜`必须在 `单一主运镜` 中声明切镜次数，并在对应的 `可见衔接` 单独写机器可验收的完整摄影事件。每个事件至少包含：`镜头事件：<时间>秒；类型：硬切/匹配切/插入/甩镜；触发事件：<画面内已发生的事件>；新机位：<方位、景别、角度、高度、焦段或构图>；切后主运镜：<固定/推近/拉远/横移/跟拍等，以及方向、距离或速度>；信息目的：<观众此刻新增看到什么>；承接：<如何接住上一帧的动作、视线、轴线、声音或道具状态>`。切后主运镜可以是“锁定机位”，但不能省略；切镜时间必须落在真实 `framePlan` 边界上，不能落在段内任意位置。
- 内部切镜的事件数量由可见信息变化决定，不按时长固定配额。5—6个内部画面可能对应4—5次切换，也可能因动作合并而更少；只要连续镜头能够清楚承载信息，就不要为了增加事件而切镜。每个事件的机位和切后主运镜必须服务不同的观众注意力转移，不能只更换焦段或同义描述。
- 镜头发生切换时，新关键帧必须说明切换发生的时间/事件、新机位与切后运镜服务的信息，以及如何承接上一帧；不能用只改形容词的相似画面代替。跨镜头的 `transitionIn/transitionOut` 不计入本镜内部切镜。

## 静态帧适配器

静态帧使用现有 `imagePrompt` 字符串作为唯一静态画面事实源，不强制九段，也不新增 `staticFrame` 等字段。可按事实选择以下五类短段，缺少事实的段落直接省略：

`画面主体`、`可见状态`、`构图与空间`、`光色与风格`、`针对性约束`

每帧至少表达当前主体、当前冻结的可见状态，以及一项可验收的空间关系、视线、姿态、道具或环境结果。可见表演并入“可见状态”。静态帧只冻结一个已经发生的瞬间；不得写视频动作过程、时间段、运镜过程、对白、声音或内部执行信息。`actionPrompt` 只描述动作过程，不复制进 `imagePrompt`。不要从镜头描述、资产档案、NPC 策略或相邻帧补写静态正文；服务端只做轻量格式化和硬错误校验，发现缺少可选段、重复状态、景别细节不匹配、NPC 可能拥挤或构图/光线不完整时给出警告并保留原文。参考图职责只由 `referenceManifest` 和服务端执行层绑定承载，不写入 `imagePrompt`。同一镜头内每帧独立使用固定资产锚点；只有跨镜头连续性边明确要求时，第一帧才使用上一镜已人工验收的实际尾帧 `previous_accepted_actual_tail`。

## 视频适配器

视频提示词继续使用项目固定公开字段：

`素材绑定 → 动态意图 → 全局设定 → 起始可见状态 → 时间段动作 → 单一主运镜 → 环境压力与视觉母题 → 视觉风格与光色 → 声音意图 → 结束画面 → 连续性锁 → 针对性约束`

每个真实时间段逐块写出起点、动作与触发、可见衔接和终点；动作段内部按“准备/触发 → 接触或受力 → 主体动作与方向 → 受影响对象的可见结果 → 主体或对手反应”组织，事实不足时省略没有依据的环节，不得凭空补写。必须有具体时间范围，不能机械逐秒切分。动作必须能被看见，至少落到身体、表情/视线、手部/道具或环境结果；相邻段必须有真实动作差异，不能只改同义词。NPC 如被场景策略要求，时间段必须写出当前事实支持的群像数量、分布和可见反应；固定语法只用于机器验收，不得复制同一反应句。先在 `单一主运镜` 中声明 `镜头模式：连续镜头` 或 `镜头模式：内部切镜（N次）`：连续镜头的所有帧共用一个连续摄影路径；内部切镜时，每个切点必须在对应段的 `可见衔接` 写出完整镜头事件，包含时间、类型、触发事件、新机位、切后主运镜、信息目的和承接，并且切点时间必须等于某个 `framePlan` 段的起点。摄影必须写明一个有动机且包含路径的主运镜或固定机位及其服务的具体可见变化，不能只写“服务于当前信息或动作变化”；镜头切换必须写出发生时间、触发事件、机位变化、切后运镜、信息目的和承接关系，背景结构不得被虚化成无信息色块。视频 prompt 和 `framePlan.frames` 由 Agent 直接生成，应用代码只校验、保存和转发，不能根据帧计划重新拼接或补写视频 prompt。

视频时间段的最低可执行细节：有人物时，每段至少写出一个主角色的具体表情/视线/呼吸/身体/手部变化，并写出一个被触发的对手、父辈、道具或环境可见结果；有对白时，每个时间段都必须包含 `对白表演：说话人；语气；停顿；重音；说后反应`，对白结束后的段落也要明确写出反应停顿或静默结果。场景策略为 `required` 的 NPC 必须在每个受事件影响的时间段写出固定 `NPC群像` 语法，并且至少出现一次不同于前段的可见群像反应；不能只在“环境压力与视觉母题”中概括群体反应。“准备回应、承受压力、情绪加剧、保持状态、自然反应”等抽象短语不能代替上述可见事实。

## 制作包适配器

制作包镜头必须把导演判断落到现有字段：

- `shots` 是叙事上的逻辑镜头，不等于 `framePlan` 的时间段；Agent 必须先决定哪些信息属于同一镜头，再决定镜头内是否连续拍摄或发生内部切镜。生产方案的 15/30 秒预算不能把一段复杂对白强行压成连续镜头，也不能为了凑镜头数把一个可连续承载的动作拆碎。
- `cameraMotion` 与 `videoPrompt` 必须互相解释：连续镜头写一条贯穿路径；内部切镜按每个切后段写独立的机位和主运镜，并让每个镜头事件说明为什么此刻改变观众的视觉注意力。

- `dramaticFunction`：唯一戏剧职责和情绪/压力变化。
- `performancePlan`：起点、中段、终点的可见表演变化。
- `performancePlan` 与 `continuity.actionStart/actionEnd`：动作的支撑、接触/受力、方向、结果和反应；不要只写动作名称。
- `lightingPlan`：色板、色温、光源方向、材质反应、肤色保护和前后镜衔接。
- `continuity`：景别、机位、构图、站位、视线、动作起止、屏幕方向和轴线；同镜头关键帧独立生成，`previous_accepted_actual_tail` 只允许作为跨镜头第一帧的入口连续性依据。
- `lens`、`cameraMotion`、`transitionIn`、`transitionOut`：摄影与转场的可执行选择；`cameraMotion` 只写相机路径，不把主体动作和环境运动混成第二套运镜。
- `entryState`、`exitState`：本镜头可被下一镜继承的事实状态。
- `backgroundNpcPolicy`：场景默认/必须/禁止背景 NPC，以及本镜头实际采用的数量、分布和行为；NPC 不进入角色资产引用。
- `videoPrompt` 的 `素材绑定` 和镜头 `characterCodes`、`locationCode`、`propCodes`、`clueCodes` 必须互相一致；正文不得提及未绑定道具。环境母题、负面约束和素材绑定都必须从当前镜头声明资产推导，不能把某一镜的契约、武器或其他道具硬编码到所有镜头。
- `productionPlan.references.maxImages` 必须随镜头时长生成：15 秒及以下为 9，30 秒为 30；这只是短剧编排预算，供应商实际声明的更小能力仍由运行时能力校验决定。

不得新增重复章节，不得用占位词代替当前节点事实。

## Agent 制作包 provenance 与统一入口

短剧制作包的正式生成入口只有项目服务端的 `executeDramaScriptRun`：它把当前用户请求、正式项目事实、用户本轮模板/TXT/参考素材、锁定生产方案和本 Skill 的当前编译内容作为 authoring input 交给项目 GPT。模板只决定字段/章节格式，TXT 只提供剧情事实，两者必须都被读取；固定脚本、历史制作包、旧 generationPrompt 或直接从模板复制正文都不能冒充 authoring。

Agent 先返回符合 `vozeb-drama-production-package-v1` 的 authoring draft；服务端只做事实与质量门禁，然后使用规范对象确定性序列化为最终 JSON/Markdown 制作包。最终包必须记录 `authoring.source=executeDramaScriptRun`、本 Skill 的 id/version/contentHash、Seedance 2.5 Skill 的 id/version/contentHash，以及模板/TXT/参考素材的 alias、role、顺序和 contentHash。缺失 provenance 或不是该正式入口的生成结果，不得作为项目 Agent 制作包完成。

内部项目 GPT 和用户显式调用的 Codex 导演审阅都必须从同一份 `.agents/skills/drama-video-director/SKILL.md` 编译产物读取相同版本与内容哈希；Codex 侧不得维护一份手工规则副本，项目服务端也不得注入第二套冲突的导演规则。

## 门禁分层

硬门禁只处理事实和可执行性：资产引用、人物/道具/空间是否真实、当前帧是否有可见状态、入口/出口状态、实际尾帧、时间轴、参考职责和连续性依据；Agent authoring draft 还必须通过动作差异、情绪递进、required NPC 反应变化、运镜动机和镜头事件检查。

软警告处理电影化质量：光源动机、焦段与机位意图、纵深机制、景深使用、轴线风险、节奏重复、高潮停顿、非人物镜头职责和空泛电影术语。经验比例、固定运镜次数和题材偏好不得直接阻断生成。

## 外部 Codex 调用

当 Codex 任务涉及制作包、分镜、片段帧、首尾帧、视频提示词、切镜、运镜、光影或连续性时默认执行本 Skill；用户无需再次显式选择。只有普通问答、与视觉生产无关的文本任务或用户明确要求不做导演化改写时不执行。输出应说明发现的问题、保留的事实和可直接替换的公开字段；不得把内部规则、模型理由、供应商参数、内部 ID 或思维链写入公开提示词。

## 项目定制规则

执行优先级固定为：本次用户补充要求 > 项目保存的 `customDirectorRules` > 当前剧本与资产事实 > 本 Skill > 系统默认。项目定制规则长期影响制作包、图片帧优化、视频提示词优化和外部 Codex 工作单，但不得覆盖真实资产、连续性验收结果、供应商能力或用户本次明确修改。
